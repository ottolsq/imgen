# imgen — AI 图片资产制作 Skill

把一句需求变成成套、可直接复制到生图工具使用的**图片提示词与锚定文件**。面向零绘画/影视基础的用户：风格、构图、光线、锚定与提示词工程由本 skill 补全，用户只在两个确认点做决定。

> **交付的是提示词与锚定文件，不是图片**——本 skill 不调用任何生图 API，也不替代生图工具。
>
> **本 README 是开发文档，只做介绍与导航，规则全文以各 references 文件为唯一权威**；本文件保留的流程概览仅供快速了解，不构成规则权威。本文件与 `tests/` 在**运行时永不读取**。

## 与 vigen 的关系

imgen 提取自 **vigen 2026-11-01 版本（源 commit `82f2be7835e829996ae2b205e599284cd17c76a1`，冻结快照）**，提取日期 **2026-11-01**。

- 采用**复制提取**：把 vigen 中与图片资产相关的规则整段复制进新仓库，再逐条改写为图片语境（去掉视频骨架、分镜与剪辑等视频专属语境）。
- 两个仓库**各自独立演化、不互相同步**。源 vigen 正在独立升级，imgen 不追；将来需要人工比对时，以本节记录的源 commit 为基线。
- vigen 工作区中的改动属于其自身升级，与本仓库无关；imgen 的提交历史只触碰 `imgen/` 路径。

## 不做什么（能力边界）

- 不生成视频成片、分镜、运镜或视频提示词——这类需求转 vigen。
- 不调用任何生图 API；交付物是提示词与锚定文件，图片由用户在自己的工具里生成。
- 不写剧本/故事板；画面需求只到"这张图怎么拍/怎么画"为止。

## 第一次使用怎么读

1. 读 `SKILL.md` 的 Module Map 与规则归属表，知道每条规则的家在哪。
2. 按工作流跑：GATE0 问卷 → 阶段1 锚定（GATE1 停）→ 阶段2 矩阵与提示词。
3. 只在写对应资产时打开该资产的家文件；扩展知识先查 `knowledge-index.md`。

## 工作流（两停点一图流）

```
GATE0 问卷+对齐 → 阶段1 锚定 ─GATE1（必须停下）→ 阶段2 资产矩阵+提示词 → 交付摘要
```

- **GATE0**：资产类型与清单、用途、生图模型+供应商、画幅、风格、表演基调、数量与优先级，一次问全；有矛盾/模糊/缺失就对齐，不脑补。
- **阶段1 锚定**：定风格 → 立即定色彩基调（3-5 个十六进制色号+落点）→ 写角色/服装/道具/场景锚定短语 → 冻结风格圣经 → 登记目标模型与供应商。
- **GATE1**：呈现锚定短语全文+风格圣经全文+色彩基调+模型，用户确认后冻结。
- **阶段2**：先查存量 → 资产引用矩阵先行 → 出锚定图（0a 三视图 / 0b 面部特写 / 道具 / 场景）→ 出情景图（互挂参考+H1-H4 分级）→ 首批验收 → 铺量并按结果状态五级登记。

**项目产物**：`01_需求与对齐.md`（问卷/对齐/变更/校验）、`02_锚定表.md`（模型/风格/色板/各类锚定，GATE1 冻结）、`03_图片提示词.md`（矩阵/提示词/结果状态）。

## 开发纪律

1. **规则单一权威（重复即缺陷）**：每条规则只有一个"家"，见 SKILL.md 的规则归属表；同一规则出现在两个文件，迟早漂移。发现重复时保留归属表里的家，其余改为指针。
2. **实测教训不许删**：带"实测教训/实测依据"的段落是踩坑换来的，重构措辞时可以改语境，但不能删掉教训本身。
3. **扩展文件命中才读**：expressions / extended-views / cinema-grade-params / emotion-craft / content-safety / exemplars 只有命中 knowledge-index 的场景才打开；未命中一个都不读。（exemplars 的命中场景：写动漫/风格化角色设定卡；用户交新范例。）
4. **参考图驱动生成模式的单一权威**在 `consistency.md` 三·五节——其他文件只引用，不复制展开。
5. **本 README 与 `tests/` 运行时永不读取**：其中出现的视频/开发类词汇不构成 skill 的运行指令。

## 修改流程

1. **先改"家"文件**：按 SKILL.md 规则归属表找到该规则的唯一权威文件，只改那里。
2. **再查指针**：`grep -rn "被改的短语" references/ assets/ SKILL.md`，把所有指向旧措辞的指针同步更新；确认没有第二份拷贝。
3. **跑全库终检**：核对被引用的 `.md` 都存在、无未收录文件指针、无视频/分镜残留、分级只用 H1-H4。
4. **提交**：`<type>: <description>` 格式，一次提交只做一个主题。
