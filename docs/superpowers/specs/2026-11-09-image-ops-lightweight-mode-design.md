# imgen 轻量分析与编辑模式 · 设计 Spec

- 日期：2026-11-09
- 状态：待用户评审
- 范围：imgen skill（SKILL.md + references/ + assets/templates.md）

## 1. 背景与目标

用户提出六项能力诉求，并反馈现有工作流中"角色面部、动作提取仍有漂移"：

| # | 诉求 | 现状判定 |
| --- | --- | --- |
| 1 | 角色融入场景 | 生成式已覆盖（互挂参考）；**已有图合成缺专用配方** |
| 2 | 图片风格迁移 | 提取再生成已覆盖（解梦卡）；**编辑式迁移缺工作流** |
| 3 | 图片提示词反推 | 仅一句提及；**缺独立工作流与边界** |
| 4 | 图片视觉风格提取 | 已覆盖（styles.md 解梦卡）；**缺轻量入口** |
| 5 | 去AI味真实感人像 | 已覆盖（realism 词库）；**缺整合出口** |
| 6 | GPT 图片去噪点 | 生成端预防已有（颗粒限档/塑形约束）；**已有图清理缺路径与保真边界** |

漂移问题的根因分析（详见 §5）：现有规则覆盖大部分场景，缺口在**反推产物被误当锚定、脸区像素无验收、编辑链无放弃阈值、动作被文字转述而非图锁、无身份验收闭环**。

**目标**：
1. 六项诉求全部有明确入口——能做的给工作流，做不到的明说边界
2. 漂移从"反复试"变为"可归因、可回上游"
3. 不破坏现有 GATE0→GATE1→阶段2 主线，不制造规则重复

**非目标**：
- 不调用生图 API（skill 边界不变）
- 不承诺消除漂移（官方明确跨生成一致性有限）
- 不改动 vigen 相关内容

### 3.1 开头：执行模型能力自检（全局前提）

开工三问：**能读图？能读文件？能写文件？** → 三层降级：

| 层 | 条件 | 行为 |
| --- | --- | --- |
| L1 完整 | 可读图 + 可写文件 | 全流程 |
| L2 无视觉 | 不能读图 / 读图分辨率不足以核对细节 | 用户口述模式：向用户逐项确认，只做结构级描述，报告明标"参考图未由模型核验"——模式 A 在此层 = 用户口述 → 按槽位结构化整理，置信度统一标"来自用户口述" |
| L3 无文件工具 | 不能写文件 | 聊天内交付，明示"未落盘" |

**归属裁定**：本表是能力自检与降级路径的**唯一权威家**；consistency 三·五末节"降级路径"原为参考图驱动语境的局部版，改为指针指向本节（避免两份拷贝漂移）。读图分辨率不足时：只做结构级反推（媒介/构图/光位/色板近似），**不做五官级断言**。

### 3.2 四个模式（每个含：输入 → 步骤 → 输出契约 → 作用域声明模板 → 验收 → 边界）

**模式 A · 提示词反推**
- 输入：用户已有图
- 输出结构化字段**对齐 prompt-rules 图片 12 槽位**（媒介/主体/姿势动作/构图机位/景别/光线/色调色板/视觉张力/风格语法/画幅/约束）——对齐的好处：反推结果稍加改写即可作为"以这张图为参考"的新提示词草稿。风格语法沿用解梦卡三层拆解法（场景事实不复述、视觉语法提取、条件项裁决——指针到 styles.md，不复制）
- 每字段标置信度：高（结构级）/ 中（色板近似——十六进制为模型估值）/ 低（五官级细节——**默认不输出**，除非用户口述确认）
- **硬边界**：反推产物禁止直接当锚定；要当锚定必须"用户逐项确认 + 参考图承载身份"，走升级通道
- 模式 A 内嵌"风格提取"快捷出口：只取风格语法字段 + 色板 → 并入 02 或聊天交付，即诉求 #4 的轻量入口

**模式 B · 风格迁移**
- 两条路径：①提取再生成（走 styles.md 解梦卡，指针）②**编辑式迁移**（新增）：底图 `Image 1` + 风格参考 `Image 2`，套用 prompt-rules 4·五 微编辑骨架（CHANGE ONLY=艺术风格 / PRESERVE EXACTLY=identity/pose/composition/文字内容——清单逐字写全），**不另立编辑配方**，只补迁移特有的注意项
- 迁移范围三档（强继承/条件继承/默认不迁移）指针到 consistency 参考图角色路由，不复制
- 边界声明：生成式编辑不保证像素级保留（models.md 边界），构图微变属正常

**模式 C · 角色融入场景**
- **路径选择判据**（与 consistency 三·五的分工）：只差"把人放进这个既有场景"，场景图为定稿底图 → 编辑式（本模式）；要生成**新画面**（新角度/新状态/新光线）→ 生成式互挂参考（consistency 三·五）
- 输入：场景图（底图）+ 角色锚定图（0a/0b 或既有成图）+（可选）姿势参考
- 配方五件套：**尺度锚**（用场景内参照物写比例，官方句式 `child-sized relative to the table` 同源）/ **光源匹配**（从场景图读光向+色温，写进提示词）/ **接触阴影**（脚底/倚靠处投影，防"漂浮感"）/ **透视一致**（机位与场景图同焦段）/ **身份保留句**（官方换装范式变体：不改脸/五官/体型/身份，only placed into the scene）
- 作用域声明：场景图锁空间+光线；角色图锁身份；姿势图只锁动作几何

**模式 D · 清理与去噪**
- D1 生成端预防：指针到 realism（颗粒限档/塑形约束/暗部通透/质量档/尺寸）+ 噪点排查表也放 realism（§4.3），此处只留入口
- D2 已有图清理（含去噪、去AI味表面重绘）：编辑式，套用 prompt-rules 4·五 骨架（CHANGE ONLY=表面纹理/噪点；PRESERVE EXACTLY=构图/身份/姿势/文字），**不另立配方**；**保真边界明示**：生成式重绘不承诺"只去噪不改内容"，需要逐像素不变走外部工具（回退出口）；去AI味重绘引用 realism 词库（指针）

### 3.3 通用验收三查

1. **身份查**：人物脸与角色参考图是同一人吗（对照 0b 或用户确认）
2. **结构查**：构图/机位/姿势/空间关系与意图一致吗
3. **表面查**：噪点/纹理/色偏处理到位且未伤主体

三查是**轻量模式内部的验收**；项目内情景图仍走拿图四扫（prompt-rules 一·3）——两套验收各管各的域，不合并。prompt-only 交付时三查标 OPEN（未执行），不标通过——沿用现有反虚报纪律。

**漂移归因表**（症状 → 根因 → 处置）：

| 漂移 | 根因 | 处置 |
| --- | --- | --- |
| 脸漂 | 文字与参考图打架 | 身份只写锁定句，细节交给面部特写图（已有规则，归因表收口） |

| 脸漂 | 多张脸参考竞争 | **同一提示词内只挂一个身份权威**（0.4 标准 5 的补充） |
| 脸漂 | 多轮编辑累积 | **编辑链放弃阈值：同一图编辑 ≥3 轮仍漂 → 放弃编辑链，回锚定图重新生成**（新规则） |

## 5. 设计原理：为什么这样切

- **轻量模式独立于 GATE0**：反推/去噪是一次性任务，塞进问卷会强迫零基础用户回答无关问题（画幅/表演基调/资产清单）；但产出仍受"文件即真相 + 反虚报"纪律约束
- **反推禁止当锚定是安全底线**：识图是降采样语义级，反推写下的五官细节是猜的；当作锚定 = 把猜测逐字冻结进全项目。锚定的信息源只有两个：参考图像素 + 用户确认
- **漂移处置的统一原则是"回上游"**：脸漂回锚定图、动作漂回锁姿图、结构漂回资产规划——所有新增规则都在强化"回上游"而不是"在坏图上修"
- **重复即缺陷**：迁移三档、解梦卡、降级路径、去AI味词库全部已有家，新文件只写指针；新增的只有四模式工作流、归因表、验收闭环、放弃阈值、脸区像素验收

## 6. 执行模型差异的应对（回应：产出质量与执行模型有关吗）

有关，且不可消除。skill 的应对策略是**降方差而非提上限**：
- 能力自检（§3.1）让弱模型明示降级，不假装读图
- 输出契约（结构化字段/置信度/验收三查）让产出可被用户校验
- 硬规则 13 拦截最危险的失败（编造细节当锚定）
- 主流程不受影响：GATE 停点、文件即真相、Module Map 本身就是对弱执行模型的约束

## 7. 测试计划（writing-skills TDD：先基线后规则）

**基线（RED）**——3 个场景各派一个无新规则的子代理，记录失败模式。**基线必须跑在改动之前**（实测教训见 tests/verification-record.md §15.3：子代理启动于改动前、完成于改动后 = 基线污染，RED 作废）——实施顺序里 RED 因此排在第 1 步：

| 场景 | 预期基线失败 | RED 实测（2026-11-09） |
| --- | --- | --- |
| "反推这张图的提示词"（给一张人像图；测试者追问"把这角色登记进项目吧"） | 编造五官细节、无置信度、把反推结果直接当锚定用（第二拍专测硬规则 13 要拦的失败） | **未失败**（代理援引三·五禁令+锁定优先级，锚定保持 OPEN 草稿待用户确认，未直接当锚定）。**但自报三处自创**：①反推工作流本体（输出结构/置信度方案/占位写法）全自创，本体只有 realism 六·6 一句雏形；②"轻量任务无入口"——意图路由四分支不匹配此形态，属真实缺口；③"对齐 vs 直接交付"以"执行+随附问题清单+全 OPEN 不冻结"自行裁量。**测试缺陷披露**：测试图片实际不存在（未创建），三代理均被推入 L2 无视觉路径——"可读图→编造五官"的 L1 失败路径**未激活**（未测，非证伪）。硬规则 13 依据回归"收口既有原则"（转述即猜测），非 RED 实证 |
| "把这张图换成赛博朋克风格" | 不写保留清单、不声明保真边界、不分工参考图 | **编辑配方未失败**（Image 1/2 分工、CHANGE ONLY/PRESERVE、反虚报全部到位——4·五 骨架已被基线正确复用）。**真失败两处**：①需求三读法（只改光/换背景/连服装改）未对齐就自行选边交付——该停的点没停；②读不到风格图时无法走解梦卡，自行拼凑"预设词条+挂图让模型自己读"的降级组合，色调冲突风险推给用户手工修。**模式 B 规则校准**：重点从"编辑配方"转向"歧义停点（意图读法枚举→问用户）+ 无视觉降级的标准动作" |
| "把这个角色放进这个场景" | 无尺度锚/光源匹配/接触阴影、参考图不写作用域 | **部分失败**：Image 1=场景/Image 2=角色分工✓、双向作用域✓、光线匹配✓、尺度锚✓（台面与胯腰齐平）、回退阶梯✓。**真失败三处**：①接触阴影缺失——只写泛化"阴影匹配"，落点不指向脚底/倚靠处（五件套预判证实）；②配方现拼——子代理自述"三·五无角色-场景合成行，由互挂参考+编辑端点+官方多图要点拼装"（强模型拼得好，弱模型会拼散）；③槽位降级无明文——生活痕迹/色板/风格圣经槽在"无 02、读不到图"时的"以 Image N 为准"承接是自创。**模式 C 校准**：配方五件套收编成正式行（三·五配方表加"角色-场景合成"行）；接触阴影写法落点化；三槽降级形式明文 |
| **跨场景模式**（2+3） | — | 两代理同触"对齐义务 vs 一次性交付"矛盾，都以**默认值显式化+变体覆盖**化解且效果好。**轻量模式对齐规则校准**：可枚举歧义（≤3 读法、每读法可自成变体）→ 默认+变体交付不阻塞（收编成正式规则）；不可枚举或影响下游的歧义（如反推→锚定登记）→ 必须问 |

**验证（GREEN）**——合入规则后重跑同场景，对照验收三查与硬规则 13。
