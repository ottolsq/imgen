# 轻量分析与编辑（image-ops：反推 / 风格迁移 / 角色合成 / 清理去噪）

> **命中"分析或编辑已有图"的一次性任务时读本文件**——用户要的是对已有图做反推/迁移/合成/清理，或从已有图提取风格，**不是产出成套资产**（那走 GATE0 项目流程）。交付物仍是提示词与分析文件，不生成图片。
> 本文件是**能力自检与降级路径的唯一权威家**；四个模式的规则与既有骨架（4·五 微编辑 / 解梦卡 / 互挂参考）只写差异与指针，不复制。

## 一、执行模型能力自检（开工三问——轻量模式与参考图驱动生成的共同前提）

**能读图？能读文件？能写文件？** 三问答完定层，层决定后续所有模式的行为：

| 层 | 条件 | 行为 |
| --- | --- | --- |
| L1 完整 | 可读图 + 可写文件 | 全流程 |
| L2 无视觉 | 不能读图 / 读图分辨率不足以核对细节 | **用户口述模式**：向用户逐项确认（媒介/构图/光位/色板/主体），只做结构级描述，报告明标"参考图未由模型核验，外观描述来自用户确认"——**不假设、不编造图里没有的细节** |
| L3 无文件工具 | 不能写文件 | 聊天内交付，明示"未落盘" |

- 读图分辨率不足 = 降 L2：只做结构级反推（媒介/构图/光位/色板近似），**不做五官级断言**
- consistency 三·五末节的降级路径（参考图驱动生成语境）即本表的局部应用，以本表为准

## 二、轻量模式对齐规则（RED 实测校准）

**可枚举歧义 → 默认+变体，不阻塞**：用户一句话有 ≤3 种读法、且每种读法可自成变体时（"换赛博朋克风格"= 只改光/换背景/连服装改），取最可能意图做主方案，其余读法做成**单变量变体**（只换对应段，其余原样），并在交付时显式列出"本次替你定的默认值"。**不可枚举或影响下游的歧义 → 必须问**：登记锚定、影响后续成批生成、或读法间互斥无法变体覆盖时，停下问用户（对齐义务不打折）。

## 三、模式 A · 提示词反推

**输入**：用户已有图（+ 可选口述补充）。

**输出 = 对齐 prompt-rules 二节 12 槽位的结构化表**，每槽三列：**值 / 来源 / 置信度**。对齐的好处：反推结果稍加改写即可作为"以这张图为参考"的新提示词草稿。

| 置信度 | 来源与写法 |
| --- | --- |
| 高 | 图中结构级事实（媒介/构图/景别/机位/光位方向）或用户口述 |
| 中 | 色板近似（十六进制为模型估值，标注"估值"） |
| 低 | 主题默认值（无证据的合理缺省，仅作骨架，标"默认"） |
| 无证据 | **不填，标 OPEN**——五官级细节（眼型/痣/发型具体走向）即使读图也是降采样猜测，默认不输出；用户口述确认后升级 |

**骨架与占位写法**（RED 收编：代理自创的"占位+默认值双轨"是对的）：视觉槽空缺时用 `{待确认：默认 X}` 占位，不用假值填充——硬规则 1 的"补默认值"针对**待提交的生成提示词**；反推草稿是分析产物，占位即诚实。

**硬边界（联动硬规则 13）**：反推产物**禁止直接当锚定**——锚定的信息源只有两个：参考图像素 + 用户确认。要发展成项目锚定时走**升级通道**：逐项确认（附确认清单：媒介风格/年龄/体型/脸型/发型/五官/标志特征/服装/光线）→ 用户点头后才可入 02，锁定优先级按 OPEN 起步、GATE1 冻结。

**风格提取快捷出口**（诉求"视觉风格提取"）：只取风格语法槽 + 色板 → 走 styles.md 解梦卡三层拆解（场景事实不复述/视觉语法提取/条件项裁决）→ 并入 02 或聊天交付。

## 四、模式 B · 风格迁移

**路径判定**：要生成**新画面**（新构图/新内容）→ 提取再生成（styles.md 解梦卡，指针）；要对**这张图本身**改风格 → 编辑式（本节）。

**编辑式迁移**：底图 `Image 1` + 风格参考 `Image 2`，套用 prompt-rules 4·五 骨架：
- CHANGE ONLY = 艺术风格层（光色关系/氛围/背景风格化）
- PRESERVE EXACTLY = identity / pose / composition / 文字内容 + **原图画风媒介保护句**（若原图是插画，明确"保持原媒介与线条风格，不移向写实"——风格词条可能带偏画风；RED 实测：代理自创此句且必要）
- 风格参考图的作用域声明：`Image 2 只提供光色关系与氛围，不迁移其中人物/建筑/文字等具体内容`

**无视觉降级（L2）标准动作**（RED 收编——无明文时代理自创且把风险推给用户）：读不到风格参考图时，**不用预设词条硬替**——改用"Image 2 挂图让模型自己读 + 文字只写用户口述的风格关系"；若用户口述与预设词条冲突，以口述为准；交付时明示"风格参考图未核验，色号如有冲突以图为准"。

**边界声明**：生成式编辑不保证像素级保留（models.md 边界），构图微变属正常；每轮迭代重复 PRESERVE 清单。

## 五、模式 C · 角色融入场景

**路径判定**（与 consistency 三·五的分工）：只差"把人放进这个既有场景"、场景图为定稿底图 → 编辑式（本节）；要生成新画面（新角度/新状态/新光线）→ 生成式互挂参考（consistency 三·五）。

**参考图组配与排序**（编辑端点行为 3 的落地）：

| 位置 | 素材 | 角色 |
| --- | --- | --- |
| Image 1 | 场景图（底图） | base scene：空间/陈设/光源/色调/画风的权威 |
| Image 2 | 角色立绘/锚定图 | identity：脸/体型/服装（立绘脸小 → 裁面部特写作 Image 3 补挂，声明只锁脸） |
| Image 3（可选） | 姿势参考 | pose：只锁动作几何，不复刻其场景与人物 |

**配方五件套**（每件必写，缺一件就是贴图感/漂浮感/巨人症）：
1. **尺度锚**：用场景内参照物写角色比例（"台面高度约与角色胯腰齐平"；官方句式 `child-sized relative to the table` 同源）
2. **光源匹配**："角色完全由 Image 1 场景内现有光源照明，光的方向/色温/曝光与 Image 1 一致（match lighting, shadows and color temperature to Image 1）"
3. **接触阴影（落点必写具体位置——RED 实测失败点）**："角色脚底在地面投下与 Image 1 光向一致的接触阴影；手搭台面处有局部阴影"——泛化"阴影匹配"锁不住漂浮感，落点必须指向脚底/倚靠处/接触点
4. **透视一致**：机位与焦段与 Image 1 保持一致
5. **身份保留句**：不改脸/五官/体型/身份，服装以 Image 2 为准；只把角色放进场景（官方换装范式的场景版变体）

**槽位降级（无 02 文件时的标准承接——RED 收编）**：生活痕迹/色调色板/风格圣经三个槽由场景参考图承载——文字写"环境/光线/色调/画风以 Image 1 为准"，**不编看不见的色号**（编造违反"不许文图矛盾"）；**媒介句/质感/景深/视觉张力槽同样降级**（画风未知时写死任何媒介句都可能文图矛盾——GREEN 复验收编）；画风权威默认=场景图（角色迁就场景画风），用户点名反转时对调声明。

**验收加两扫**（拿图四扫之外）：⑤定稿场景保真（陈设/光源/构图与 Image 1 逐项对照——"保持"不是像素锁）；⑥模型自加内容排查（凭空文字/招牌/假品牌）。

## 六、模式 D · 清理与去噪

**D1 生成端预防**：症状→原因→写法排查表见 realism.md 噪点排查表（§新增节，唯一的家）——颗粒限档/塑形约束/暗部通透/质量档与尺寸的组合。此处只留入口。

**D2 已有图清理**（去噪/去AI味表面重绘）：编辑式，套用 4·五 骨架——CHANGE ONLY = 表面纹理/噪点/颗粒；PRESERVE EXACTLY = 构图/身份/姿势/文字/色调结构。**保真边界必附**：生成式重绘不承诺"只去噪不改内容"——皮肤/材质细节会被重画，微变化属正常；需要逐像素不变的区域走**外部工具回退出口**（局部去噪/合成由外部编辑器做，skill 只负责生成端的替代重生成方案）。

去AI味重绘的表面词引用 realism 词库（指针，不复制）。

## 七、通用验收三查（轻量模式内部验收）

1. **身份查**：人物脸与角色参考图是同一人吗（对照锚定图或用户确认）
2. **结构查**：构图/机位/姿势/空间关系与意图一致吗
3. **表面查**：噪点/纹理/色偏处理到位且未伤主体

三查是轻量模式内部的验收；项目内情景图仍走拿图四扫（prompt-rules 一·3）——两套验收各管各的域，不合并。prompt-only 交付时三查标 OPEN（未执行），不标通过——反虚报纪律。

## 八、落点与登记

- **默认平铺**：`00_分析与编辑.md` 放当前工作目录（不建目录——轻量模式不建项目结构）；分析对象属于既有项目时放入该项目目录
- 模板见 assets/templates.md（模式标签/输入图登记/能力自检层/提示词/置信度/三查结果）
- **升级通道**：分析产物要发展成成套资产 → 转 GATE0 正常流程；反推/提取结论可带入新项目 02（登记来源"反推/提取自 {图}"，锁定优先级 OPEN 起步、GATE1 冻结）
