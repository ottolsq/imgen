# 一致性锚定机制（角色 / 服装 / 道具 / 场景 / 色调）

> 建 02_锚定表时读本文件。原理：**参考图 > 文字锚定 > 无锚定**，双保险 = 锚定短语逐字复用（文字层）+ 参考图多图输入（图像层）。

### 场景锚定（每个场景）
| 字段 | 说明 |
| --- | --- |
| 场景描述锚 | {空间结构/主要道具/材质}固定文字 |
| **场景母版（多画面场景必写）** | 场景母版 ID（SC01）+ **四向锚**：以画面为参照系，左/右/中央/远后方各登记一个固定物（"左侧固定为翻倒燃烧公交车，右侧固定为燃烧广告牌，中央固定为破损隔离带，远后方固定为破碎高楼与高架桥"）——跨画面空间感靠方向+固定物，不靠复述全场景 |
| 光线锚 | {时段+方向+色温}；多光源场景登记编号光源表（L01/L02/L03=来源+方向+色温K+强度%+硬软+动态行为+落点，写法见 cinema-grade-params.md）；**同场景异时段**：登记基准锚 + 变体锚（如黄昏 L01/L02、深夜 L01'/L02'），情景图按所属时段逐字引用对应变体，空间仍由场景母版锁（基准参考法） |
| LOCATION MAP | 多角色场景必写：各角色/关键道具的固定位置、朝向、相互距离（防跨画面瞬移）；单角色场景可省。**距离常数**：关键空间关系写死成常数并逐画面复述——对峙距离（"两人相距十步约六米"，一步≈0.6米）/追逐距离（"前后相距八步约五米"）/贴身距离（"不到半臂"）——实测教训：不写死，模型每张画面自取距离，用户连改三次；情景图提示词必须复述该画面适用的距离常数 |
| 参考图路径 | 场景参考图；用于 ≥3 张画面或需多机位素材 → 四视图全套（母版/对向回望/45°斜角/垂直俯拍，见 extended-views.md）全部登记 |

### 空间布局登记（情景图站位的地基——防"每张画面长出一个新世界"）

1. **从场景图认家具，不从提示词认**：场景参考图生成后，从**图里实际可见**的物件中登记 4-20 件能站/能坐/能倚的东西——提示词里写了但图上没有的家具**不许用于站位**（实测事故：让人坐在图上不存在的高台，每张画面模型各自发明一个高台，张张不一样）。**prompt-only 顺序**：本 skill 交付提示词时，站位物件先标"规划/OPEN"；场景图实际生成后由用户回填确认，再定情景图站位——与"从场景图认家具，不从提示词认"同一纪律，不得把图上没有的物件当可用站位
2. **每人一条走位记录**：在哪件东西的哪一侧 + 沿该侧多远 + 坐/站/倚 + 八方位朝向（面朝北/面朝门口）。位置写"哪一侧"，**不写坐标**（语义绑定第一层：模型没有坐标系）
3. **站位句由记录生成**，一句自然语言（"沈知微站在岸端土坡上面朝北，林枫坐在渡口条凳东端；其余座位空着，没有其他人"）——情景图提示词的主体位置槽照抄
4. **群演默认 0**：剧本没写有别人，走位句就显式写"没有其他人/其余座位空着"——不写这句，模型会把空位画成有脸的陌生人（背景围观群众是最常见的画面污染）。**边界**："默认 0"只排除**未被剧本/用户授权**的背景人物；用户或剧本显式要求出场的角色（哪怕"剧本没写但他必须出现"）计入在场声明——走位句写法："除了她与柱子另一侧的{授权角色}，再没有其他人"
5. **同场景成套画面不挪位**：无叙事驱动的系列画面，人物位置不变，只允许改朝向/坐站——每次重新生成都是重新掷骰子，位置不动骰子就少掷一次

### 道具锚定（每个命中判定规则的道具）

**哪些道具入本节**：命中六条判定规则任一即入表——判定全文见 **prompt-rules.md 一节·骨架 0（角色视觉锚定资产）的道具判定规则**（唯一的家）。要点：跨画面出现、触碰变状态、会位移、剧情承载、画面要对焦、角色强关联随身物。

| 字段 | 说明 |
| --- | --- |
| 道具锚定短语 | {名称/材质/颜色（含十六进制色号）/尺寸/磨损痕迹/标志性细节}固定文字，逐字冻结 |
| 状态清单 | 该道具在剧中出现的所有状态（收起/打开、旋紧/旋开、完整/破碎）——**每个状态一张参考图**；**可分离组合道具每部分单独一张**（拆分理由与画法见 prompt-rules.md 一节·骨架 0）；状态间**互参声明**（"破碎态=完整态被击碎的碎片，同一物件"）。可分离组合道具的锚定短语按部件分条登记 |
| **持械手/鞘位** | 武器类必填三要素：**持械手**（右手持刀/已脱手）+ **鞘位**（空鞘挂左腰侧/收入背后）+ **双手占用**（另一只手空着/抓着桥栏）——同一道具同一时刻只有一个状态（防"腰间入鞘+手中出鞘并存"），转换过程显式写（"从腰间鞘中拔出，鞘留在腰上"）。**无鞘武器（骨矛/短棍/石斧）写"无鞘"，另填收纳位**（靠墙/挂腰/随身/斜靠石台），不虚构一个鞘 |
| 参考图路径 | assets/{道具名}_{状态}.png（白底道具图，配方见 prompt-rules.md 骨架 0d）；**图案类道具**用图案特写锚定图（纯色底、图案占画面 70%+、平铺无透视变形） |
| 连续性规则 | 该道具跨画面/跨批次的状态延续说明（"沿用上一条已在桌上的那枚银锭，不重新变出新的"） |
| 链接画面 | 该道具入画的画面编号——03 对应情景图的参考图组配必须链接其参考图（防"道具在画面里凭空变了样子"） |

### 风格圣经（全局唯一）
从 styles.md 选定后逐字冻结，追加到每条图片提示词末尾。

**多世界/双场景项目的词条适配（逐字冻结的唯一例外通道）**：全片含语义差异极大的多个世界（现实站台 vs 回忆院子）时，某条风格词条在另一世界语义不成立（"霓虹倒影"进夏夜院子）——处理规则：①冻结时即登记**场景变体**（02 风格圣经节按场景分列变体词条，如"院子世界：檐下灯泡的微弱暖光在湿石板上拉出短倒影"——保持同一视觉语法关系、替换载体物）②每条提示词只逐字使用**所属世界的变体**，不硬塞不成立的词条 ③变体登记后同等冻结，中途不改；未登记变体而自行改词 = 违反逐字规则。单世界项目不适用本节，仍全片一条圣经。

### 色彩基调（全局唯一，十六进制色板——先于生成任何场景图定）

| 字段 | 面积 | 说明 |
| --- | --- | --- |
| 环境底色 | 约 60% | 空间主色（墙面/天空/地面），定调 |
| 中间调 | 约 25% | 家具/服装/道具主色 |
| 点缀色 | 约 10% | **只给特定物体**（打火机/花/招牌），不铺满 |
| 肤色基准 | — | 人物皮肤；冷环境里保留血色才真实 |
| 暗部色 | — | 阴影带色相，不是纯黑 |

进图片提示词色调槽的形式 = **色号 + 颜色落在哪里**（不只列色号，更不写"暖色调/低饱和"倾向词）。选定后与风格圣经同等逐字冻结；成套画面色调一致靠色板锚定。推荐色板见 styles.md 色彩基调节。

## 二、锚定短语写作规则

**锁定优先级三级链（冲突时的裁决顺序）**：`USER-LOCKED > 参考图/风格提取的既定裁决 > 系统默认补全`
- **USER-LOCKED**：用户在 GATE0/GATE1 显式选择或修改过的项（锚定短语/色板/风格/风格与色板的选择）——**永不被系统覆盖**，要改必须回到对应 GATE 重新确认
- **OPEN**：skill 按主题补全的默认值——可被用户参考图的迁移裁决填充，也可被用户随时改
- 02 锚定表各字段默认视为 USER-LOCKED（因为经过 GATE1 确认）；GATE1 之前的草稿期标 OPEN
- 候选写进提示词 ≠ 用户已接受——GATE1 呈现过的才是接受

1. **具体到可指认**：`28岁女性，齐肩黑色短发微卷，左眉角一颗小痣，米白色针织衫配浅灰阔腿裤，清瘦`✓；`一个年轻女性`✗
2. **顺序固定**：年龄性别→体型脸型→发型发色→五官特征→服饰→配饰。跨画面复用时顺序不变
3. **7-9 个视觉要素**：太少不够锚定，太多稀释重点
4. **道具同理**：材质/颜色/尺寸/磨损逐项具体，`一把长柄黑伞，伞面有轻微使用褶皱，木质伞柄`✓
5. **着装状态逐部位列明"有/无"（V2.9——实测教训：锚定写"上身无衣物"，生成时模型仍给角色加了肩带披挂）**：单一否定句锁不住着装——模型对"无衣物"的先验会自动补配饰/遮挡物。角色处于非常规着装状态（裸露/半裸/破损/泳装/盔甲卸下）时，锚定短语与受影响画面的提示词必须**逐部位列有/无**：`肩带无/披挂无/护臂无/腰带无/腰间兽皮裙有/腕部藤蔓环扣有`——与 02 锚定表逐字对齐，跨画面逐字复用。常规着装（完整现代/古代服饰）不需要此清单，写全服饰要素即可
6. **年轻人物皮肤状态标准句（基础句 + 微笑追加句，逐字复用）**：
   - **基础句（所有年轻人物画面逐字插入）**：`年轻紧致、表面平滑细腻，面颊与额头饱满平整，眼周与口周皮肤舒展，保留真实毛孔。`
   - **微笑追加句（仅表情为微笑/含笑的画面插入）**：`微笑时苹果肌自然隆起，面颊轮廓圆润连贯。`
   说明：与质感槽的 `natural skin texture, visible pores` 并存；非微笑画面只插基础句，避免"微笑"描述把中性/对峙表情带偏。**年轻人物微笑描述**：用苹果肌隆起/嘴角上扬/下眼睑轻收，不写"法令纹加深/皱纹挤出"（与基础句的"平滑/舒展"冲突）。

## 三、跨资产一致性操作规则（图片端多图参考）

### 图片端（多图参考）
- **参考图六条硬标准 + 数量上限**：全文见 **prompt-rules.md 0.4 节**（唯一的家）。本处只留判定要点——一张图只回答一个问题，脸和身子分开，3-5 张最优 ≤8（超 10=噪声），禁九宫格拼贴设定卡
- **角色资产 = 三层分工**（AI 只识别像素/轮廓/五官比例，不读图中文字）：视觉锚定层（三视图主锚+面部特写+按需补充锚）/ 文字规则层（锚定短语进提示词）/ 人工参考层（拼贴卡自看，绝不整卡上传）
- **头身分离必须落到出图动作上**（实测教训：规则写了，实际生成时没分开——一张图同时画全身和脸，脸只占两三成，一致性当场失效）：03 的人物参考图节**按 templates 0a/0b 分两张出图**——0a 白底三视图（只管比例/服装/轮廓，脸裁掉或转过去）+ 0b 面部特写（脸占画面 6 成以上）。**不许合成一张"设定图"交差**（**例外仅限动漫/国漫设定项目**：可用 cinema-grade-params 二节的四视图配方合出，或按 prompt-rules 0e 九段结构出单图设定卡——均须脸区占足像素，见 SKILL 硬规则 7）
- **互挂参考（人物↔场景↔情景三向引用）**：三类资产不是各自孤立出图，而是相互挂参考——
  - **情景图必挂（角色最小参考集铁律，实测教训：只挂情景图→脸漂；只挂三视图→画成兜帽）**：该画面的角色锚定图（三视图+近景加面部特写）**＋** 所在场景图（母版）→ 人物与空间同时锁住；①角色入画的画面**必挂其三视图**（次要角色可用其"链式参考"身份图替代；首现且无既有图时以 02 文字锚定承载并标 OPEN；换装画面可用目标服装的 0a 同规格全身锚替代旧三视图——详见 prompt-rules A3）；②该角色有近景/面部可见**必挂面部特写**；③两个主角的最小集（三视图+面部）**优先于任何场景视图**——挤掉场景图也不能挤掉角色图
  - **场景图可挂**：已有定稿场景图作母版基准（同场景异状态/异机位时）；道具入画的场景挂道具图防串戏（prompt-rules 0.5）
  - **人物图之间**：同角色多状态图互为参考（服装改版时挂上一版防漂回旧设定）；角色同框时挂各自锚定图，**受"一张图一张脸"限制——合成图仅作身形/服装参考，脸另给特写**
  - 每张挂入的图写**双向作用域声明**（锁什么+不锁什么），角色路由规则见本节下一条
- **基准参考法（同场景异状态画面的有效手段）**：一张已定稿的成图可作为后续画面的**基准参考**——同场景不同状态（"A31 定场全景作 S3d 动作情景基准"）、同场景异机位、同角色异动作。做法：基准图挂入该画面的参考图组并声明"只锁空间布局/光线方向/主体比例，不锁姿势与表情"。**价值**：省去重新描述整个场景，且空间关系天然一致。与"定稿标记"配套（防基准图被重生成污染）
- **参考图按画面机位动态组配**：正面画面 → 三视图（或裁出正面图）+ 场景图；侧/背画面 → 必须加对应视图；特写/近景 → 必须加面部特写锚定图；**道具入画的画面 → 加道具对应状态图**
- **参考图角色路由（每张图只有一个权威维度）**：常见权威维度=角色身份/服装/道具/场景空间/构图/光线/色彩/材质/风格语法；**显式排除收窄角色**（"只参考灯光不参考构图"→ 排除句写进用途声明）；多参考图矛盾时按维度分工各取所长，**禁止"综合一下"**（平均=谁也不是）；**风格参考图的迁移范围三档**：强继承（色彩结构/材质处理/媒介质感/曝光行为）→ 条件继承（机位/构图/尺度/光向，逐项标 Preserve/Adapt/Release）→ 默认不迁移（人物身份/服装/道具/文字/品牌）。提取方法见 styles.md 风格提取（解梦卡）
- **绑定短句化（实测教训：`{{ref N}}` 标记单独出现绑定不可靠；3 张参考输入下模型没建立"哪张图管什么"的映射；作用域长文案被长指令稀释——指令越复杂，模型越倾向只执行一部分、其余自由发挥）**：`Image N` 标记必须与职责句**同句出现**，不单独罗列；每张图一句短绑定（用途+锁定什么+不复刻什么）**紧贴其使用处**；**≥3 张图先给一行映射**（`Image 1=身份 / Image 2=服装 / Image 3=风格`）再展开细节；关键绑定放提示词**前 1/3**
- **风格作用对象逐层拆分（实测教训：一句"换成 X 风格"→模型只换背景，人物本身不受光、不吃质感）**：风格迁移分两层各写一句——**环境层**（背景/光线/色调/氛围）与**人物层**（受光方向/肤色受色/服装材质反光/发丝高光）；只给一个模糊"风格"短语=模型取最容易执行的那一项；验收加"人物层风格吸收查"（见 image-ops 模式 B）
- **绝不"编辑已生成的图"来换场景/姿势**——每次编辑累积伪影
- 多人场景：宁可拆图（每画面 ≤2 人同框为佳）
- 长会话（12+ 张）后参考图"失忆"——分批新开会话/独立请求，每次重传参考图
- **资产引用矩阵先行**（03 文件头）：零引用资产不生成，防浪费

### 色调端
- 图片端：风格圣经**全量**逐字后缀 + **色彩基调色板**（十六进制色号+颜色落在哪里）进色调槽

## 三·五、参考图驱动的生成模式（换装 / 姿势 / 表情）

> 触发场景：产出时挂参考图（换装、换姿势、换表情、角色与场景合成）。核心原理：**生图模型读参考图的像素，文本模型读参考图的语义摘要**——两者之间有天然信息差。提示词要善用图，不要与图打架。

**为什么"绝不文图矛盾"（社区经验）**：模型默认文本权重高于参考图——文字缺少强约束或与参考图冲突时，会按文本生成，参考特征丢失。因此参考图负责"长什么样"，文本只写差异项与身份锁定句；发现矛盾先修锚定/参考图，不在提示词里叠形容词对抗。

### 文图信息分工（谁说什么话）

| 信息 | 权威来源 | 提示词怎么写 |
| --- | --- | --- |
| 身份（脸型/五官/发型/标志性特征） | 面部特写参考图 | 只写身份锁定句（"SAME face as reference"）+ 锚定短语中的身份要素 |
| 服装（款式/颜色/材质/配饰/磨损） | 服装参考图 | 写"服装以 Image N 为准"，**不复述细节**；换装时使用对应版本的服装锚定短语（02 服装锚定表），不沿用旧版 |
| 身材/体型 | 全身/三视图参考图 | 只写"体型以 Image N 为准"；锚定短语中的体型描述必须与参考图一致，不一致时改锚定，不在提示词里二选一 |
| 姿势/动作 | 文本 | 明确写目标姿势；参考图声明"不复刻其站姿/姿势" |
| 表情 | 文本（FACS 物理化） | 用面部特写锚 + 物理化表情描述；不要额外喂表情参考图与中性锚同时出现且不分工 |
| 构图/机位/景深 | 文本 | 明确写；参考图声明"不复刻其构图/背景" |
| 光线/色调/场景 | 场景参考图 + 文本色板 | 写"环境与光线以 Image N 为准"，色调槽用十六进制色板 |

**三条禁令**：
1. **不许转述图**：文本模型不得把参考图"转写"成细节描述（识图是降采样语义级，转述必失真，写下的细节是猜的）。参考图里已有的外观信息，一律用"以 Image N 为准"承接。
2. **不许文图矛盾**：提示词里任何与参考图冲突的描述（旧服装词、旧发色、体型形容）都会被模型平均或随机选边——发现冲突先修锚定/参考图，不要在提示词里叠形容词对抗。
3. **不许堆词**：参考图承担外观后，提示词只写差异项（姿势/构图/表情/光线/场景），形容词堆叠会稀释参考图信号。

### 锚定短语的字段化版本（换装的头号漂移源）

- 角色锚定短语**只保留身份级要素**（年龄/性别/脸型/发型发色/标志性特征/体型），**服装描述移入 02 服装锚定表**，每套服装一条独立锚定短语。
- 换装时使用目标服装版本的锚定短语逐字；旧服装的锚定短语**不得**出现在该组提示词中。
- 服装锚定短语同样逐字冻结；服装改版时新版本挂旧版本参考图防漂回旧设定。

### 参考图角色声明（每张必写，双向）

`Image N = {素材}。锁定 {身份/体型/服装/场景结构/光线}；不复刻 {其站姿/姿势/构图/背景/景别}`

- 多张参考图必须**按维度分工**（脸/服装/场景各管一维），互相矛盾时各取所长，禁止"综合一下"（平均=谁也不是）。
- 一张图只回答一个问题；同一维度不挂两张互相竞争的参考图。

### 两步生成法（换装/多状态角色的标准链路）

1. **先出新锚**：基础面部特写锚 + 目标服装参考 → 生成"该服装版本的角色锚定图"（白底/均光/中性表情，按 0a/0b 标准）。
2. **再用新锚铺量**：后续画面只挂新锚 + 场景，不再同时挂旧锚——避免新旧设定在同一提示词里竞争（A3 已认可该替代：目标服装 0a 同规格全身锚可替代旧三视图）。
3. 新锚登记进 02（服装锚定表 + 参考图路径），作为该服装版本的基准参考图复用。

### 三类场景的配方

| 场景 | 参考图组配 | 文本职责 | 常见翻车点 |
| --- | --- | --- | --- |
| 换装 | 新服装锚 + 面部特写（+场景） | 姿势/构图/表情/光线 + "服装以 Image N 为准" | 沿用旧服装锚定短语 → 衣服回漂；挂旧版三视图 → 混搭 |
| 换姿势 | 面部特写 + 三视图（+场景） | 目标姿势写具体（FACS/身体序列），参考图声明不复刻站姿 | 未声明不复刻 → 出正立站姿；姿势描述用"自然放松"式空话 |
| 换表情 | 面部特写 + 场景 | 表情按 FACS 物理化（肌肉/瞳孔/注视），不用情绪标签 | 喂表情参考图又与中性锚冲突；只写"生气的表情"→ 表情不到位 |

**浅层/深层特征（社区经验）**：颜色、毛发、轮廓易保留；脸型结构、五官比例、姿态骨架、配饰位置易变形——深层结构必须靠图分工+文字强约束。精细特征（斑纹数量/虎牙颗数/挑染位置）用精确计数与单侧描述（"一颗，不是两颗"）。

> **官方换装范式（OpenAI Cookbook 原文，可逐字复用）**：Do not change her face, facial features, skin tone, body shape, pose, or identity in any way. Preserve her exact likeness, expression, hairstyle, and proportions. Replace only the clothing, fitting the garments naturally to her existing pose and body geometry with realistic fabric behavior. Match lighting, shadows, and color temperature to the original photo so the outfit integrates photorealistically, without looking pasted on. Do not change the background, camera angle, framing, or image quality, and do not add accessories, text, logos, or watermarks.
> （中文一句：不改脸/五官/肤色/体型/姿势/身份，只换服装并让面料自然贴合现有姿态与身体几何，光线阴影色温匹配原图，不改背景/机位/构图/画质，不加配饰文字 logo 水印。）
>
> **角色锚工作流（官方 6.4）**：先建角色锚图；后续 edit 逐项列"相同项"（同款服装/同五官/同比例/同配色）并写 `do not redesign the character`。

### 降级路径（文本模型无视觉能力时）

**规则全文见 image-ops.md 一节（能力自检与降级的唯一权威家）**——本节为参考图驱动生成语境的指针：若调用本 skill 的文本模型**不能读图**（或读图分辨率不足以核对细节）：
1. **由用户描述参考图内容**：模型向用户逐项确认（脸型/发型/服装款式颜色材质/体型/场景结构），把用户确认的描述登记为锚定短语——**用户口述 > 模型猜测**。
2. 模型只写差异项（姿势/构图/表情/光线），外观一律"以 Image N 为准"，不做任何转述。
3. 报告里明说"参考图未由模型核验，外观描述来自用户确认"——不假装读过图。

## 三·七、漂移归因与身份验收（脸漂/动作漂的定位表）

> 某张图"脸不像了/动作变了"时先查本表定位根因，再按处置回上游——**所有处置的共同原则是"回上游"，不在坏图上叠修正**。

| 症状 | 根因 | 处置 |
| --- | --- | --- |
| 脸漂 | 文字与参考图打架 | 身份只写锁定句（"SAME face as reference"），细节交给面部特写图——发现冲突先修锚定/参考图，不叠形容词对抗（三·五禁令 2） |
| 脸漂 | 脸区像素不足 | 脸区像素验收不过关（prompt-rules 0.4）：0b 脸区 <60% 或短边 <1024 → 先裁剪（裁剪不缩放）或重出，不降标准使用；立绘脸小 → 裁面部特写补挂 |
| 脸漂 | 多张脸参考竞争 | **同一提示词内只挂一个身份权威**——多张含脸的图不分工就是"综合一下"，模型平均出第三个谁也不是 |
| 脸漂 | 多轮编辑累积 + 相对微调 | **调整词绝对化**：不写"更瘦/更大/更白"（相对词逐轮叠加变量，每轮都在偏离基线——实测教训），写"脸宽与 Image 1 一致"式绝对目标；**身份敏感调整（脸/体型/发色）每轮从原始基线图重出**，不以上一轮输出为基线；常规表面微调（光线/瑕疵）才允许链式。**编辑链放弃阈值**：同一张图编辑 ≥3 轮脸仍漂 → 放弃编辑链，回锚定图重新生成（生成式编辑每轮重画，越修越漂；models.md"多轮编辑累积漂移"） |
| 脸漂 | 无验收闭环 | **身份验收闭环**：每张含角色图生成后对照 0b 逐项核（脸型/发型/标志性特征），漂了回上游重生成，不在原图上修 |
| 动作漂 | 动作被文字转述 | **图锁姿势**（prompt-rules 0.2）：从图提取动作不转述成文字——姿势参考图直接挂入，声明"只锁动作几何，不复刻脸/服装/背景" |
| 动作漂 | 参考图未分工 | 双向作用域声明（三节）——姿势图与身份图混挂不分工，模型把立绘的展示站姿带进画面 |
| 动作漂 | 无唯一姿势锚 | **同一动作跨画面：指定一张 H2 锁姿图为该动作的权威参考**，后续同动作画面都挂它——不各自重写文字描述（文字写不出复杂姿态，每写一次就掷一次骰子） |

**参考图固定排序**（编辑/多图输入时保持稳定，对齐 prompt-rules 编辑端点行为 3）：`base scene → identity → garment → style → pose`——顺序一变语义全变；重试沿用首次成功的排列。

## 四、失效传播

锚定表（02）变更时：
1. 在 03 文件头部插入标记：`> ⚠ 上游锚定已变更（变更日期），本文件待重新生成`
2. 聊天中明确告知用户哪些文件失效、需要重做哪些提示词
3. 未重新生成前，旧提示词与新锚定混用 = 一致性必然崩坏
- 02 变更同时回读所有引用该锚定的情景图提示词（改一资产回读全部引用——SKILL.md 单点修改复查纪律）
